# Neural Network from Scratch — Handwritten Digit Recognition

A feedforward neural network (784 → hidden layer → 10) that recognizes
handwritten digits (MNIST), implemented **from scratch in plain
JavaScript** — no TensorFlow.js, no PyTorch, no ML libraries. Forward
pass, backpropagation and gradient descent are all hand-written.

Includes a live browser demo: draw a digit with your mouse and watch the
network predict it in real time, with the 10-class probability
distribution shown as bars.

## Why

Built to understand — not just use — how a neural network actually
learns: weighted sums, activation functions, the chain rule applied by
hand through backpropagation, and gradient descent updating thousands of
parameters from raw pixel data.

## Project structure

```
neural-network-mnist/
├── matrix.js          # vector/matrix math: dot product, matmul, transpose, outer product
├── activations.js      # ReLU, its derivative, and softmax
├── network.js           # the Network class: forward pass + backpropagation (the core)
├── test-matrix.js        # unit tests for matrix.js — run after each function you implement
├── train.js               # Node script: loads MNIST, trains, saves weights + a loss log
└── web/
    ├── index.html          # the live demo page
    ├── style.css
    ├── draw.js               # canvas drawing -> 28x28 pixel array
    ├── predict.js             # loads the trained weights in the browser
    ├── main.js                  # wires drawing -> prediction -> UI, renders the loss chart
    ├── weights.json              # generated by train.js (gitignored until you train)
    └── training-log.json          # generated by train.js
```

## What's implemented vs. what you write

The plumbing is done: data loading (via the `mnist` npm package, already
parsed as normalized 784-pixel vectors), the training loop, evaluation,
weight save/load, and the entire browser UI (canvas, bars, chart).

**You implement the actual math**, marked `// TODO` in two files:

- `matrix.js` — `dot`, `matVecMul`, `addVectors`, `subtractVectors`,
  `elementwiseMul`, `outer`, `transpose`
- `network.js` — `forward()` (the forward pass) and `trainOne()`
  (backpropagation + gradient descent for one example)

Each function in `matrix.js` has a comment explaining what it should do
and a worked example. `network.js` has step-by-step comments for the
backprop math.

## Getting started

```bash
npm install          # installs the `mnist` data package
node test-matrix.js   # currently all FAIL — that's expected, start implementing matrix.js
```

Implement `matrix.js` one function at a time, re-running
`node test-matrix.js` after each one. Once all 9 tests pass, move to
`network.js`: implement `forward()` first, then `trainOne()`.

```bash
node train.js   # trains the network and saves web/weights.json
```

If `forward()`/`trainOne()` aren't implemented yet, this still runs but
predicts randomly (~10% accuracy — 1 in 10 chance, since there are 10
digits). Once your math is correct, you should see the loss drop and
accuracy climb epoch by epoch (65-90%+ depending on dataset size/epochs
— see tuning below).

### Running the browser demo

The demo uses `fetch()` to load `weights.json`, which browsers block
from a `file://` page. Serve the folder with a local server, e.g.:

```bash
cd neural-network-mnist
npx serve .
# or: python3 -m http.server 8000
```

Then open `web/index.html` through that server (e.g.
`http://localhost:3000/web/index.html`), draw a digit, and watch the
prediction update live.

## Tuning

Once the math works, `train.js` has a few constants at the top worth
experimenting with:

- `TRAIN_SIZE` / `TEST_SIZE` — more examples = better accuracy, slower
  training. Start at 2000/500 (seconds to train), push to 10000/2000+
  once you're confident it works.
- `HIDDEN_SIZE` — more neurons can fit more complex patterns, but also
  overfit/slow down with too little data.
- `EPOCHS` / `LEARNING_RATE` — if loss oscillates wildly, lower the
  learning rate; if it barely moves, raise it or train more epochs.

## What's next (v2 ideas)

- Swap the single hidden layer for a convolutional layer (CNN) — much
  higher accuracy on images, and a natural "part 2" of this project.
- Batch gradient descent (average gradients over a mini-batch before
  updating) instead of updating after every single example.
- Compare ReLU against GELU/Swish (used in modern architectures).

## Talking points for interviews

- Why softmax + cross-entropy makes the output-layer gradient simplify
  to `prediction - target`.
- Why ReLU's derivative (0 or 1) is simpler and faster than sigmoid's.
- The role of the outer product in turning per-neuron errors into a
  gradient for an entire weight matrix in one operation.
- Why weights are initialized small and random, not zero (zero weights
  make every neuron in a layer compute the exact same gradient, so they
  never differentiate from each other — this is called the *symmetry
  problem*).
